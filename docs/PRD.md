# BuildLog 제품 요구사항 문서(PRD)

## 1. 문서 목적

이 문서는 BuildLog의 첫 번째 버전에서 무엇을 만들어야 하는지 쉽게 설명하는 제작 주문서입니다.

`MVP.md`에서 확정한 기능과 이후 대화에서 확정한 세부 규칙을 빠짐없이 포함합니다.

## 2. 서비스 소개

BuildLog는 공부와 프로젝트 기록을 한곳에 모아두는 웹사이트입니다.

사용자는 오늘 공부한 내용, 앞으로 해야 할 일, 오류와 해결 방법을 기록할 수 있습니다. 저장한 내용은 나중에 목록과 검색을 통해 다시 찾아볼 수 있습니다.

컴퓨터와 휴대폰 브라우저에서 모두 편하게 사용할 수 있는 반응형 웹사이트로 만듭니다.

## 3. 누가 사용하는 서비스인가요?

- 오늘 무엇을 공부했는지 기록하고 싶은 사람
- 공부 계획이나 프로젝트의 할 일을 관리하고 싶은 사람
- 오류와 해결 방법을 기록해 비슷한 문제가 생겼을 때 다시 찾아보고 싶은 사람
- 자신의 기록을 다른 사용자와 공유하고 싶은 사람

BuildLog는 여러 사용자가 회원가입해서 사용하는 서비스입니다. 각 사용자는 자신의 비공개 기록을 다른 사람과 분리해서 관리합니다.

## 4. 어떤 불편을 해결하려고 하나요?

사용자는 공부와 문제 해결 내용을 메모장, AI 대화, 여러 문서에 나누어 기록합니다. 시간이 지나면 어디에 적었는지 기억하기 어렵고, 이전에 해결한 오류도 다시 찾기 어렵습니다.

또한 앞으로 해야 할 일을 따로 관리하지 않으면 무엇을 끝냈고 무엇이 남았는지 알기 어렵습니다.

BuildLog는 다음과 같이 이 불편을 줄입니다.

- 공부 기록, 할 일, 오류 기록을 한곳에 저장합니다.
- 저장한 기록을 목록과 검색으로 다시 찾습니다.
- 할 일의 완료 여부와 오류의 해결 여부를 구분합니다.
- 비공개 기록은 본인만 보고, 원하는 기록은 다른 사용자에게 공개합니다.

## 5. 사용자가 각 기능으로 무엇을 할 수 있나요?

### 5.1 회원가입과 로그인

#### 회원가입

- 사용자는 이메일, 비밀번호, 닉네임을 입력해 가입할 수 있습니다.
- 하나의 이메일로는 계정을 하나만 만들 수 있습니다.
- 닉네임은 다른 사용자와 겹칠 수 없습니다.
- 사용자는 가입 후 자신의 닉네임을 변경할 수 있습니다.

#### 로그인

- 사용자는 가입한 이메일과 비밀번호로 로그인할 수 있습니다.
- 로그인한 사용자는 자신의 기록을 만들고 관리할 수 있습니다.
- 다른 사용자의 비공개 기록은 볼 수 없습니다.

#### 첫 버전에 포함하지 않는 회원 기능

- 이메일 확인
- 비밀번호 찾기

### 5.2 기록의 공개와 비공개

- 공부 기록, 할 일, 오류 기록은 처음 만들 때 기본적으로 비공개입니다.
- 비공개 기록은 작성자 본인만 볼 수 있습니다.
- 작성자는 원하는 기록을 공개로 설정할 수 있습니다.
- 공개 기록은 로그인한 다른 사용자가 볼 수 있습니다.
- 로그인하지 않은 사람은 공개 기록을 볼 수 없습니다.

### 5.3 공부 기록

사용자는 오늘 공부하거나 작업한 내용을 기록합니다.

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 제목 | 1~100자 |
| 내용 | 1~5,000자 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 작성 날짜와 시간 | 기록을 만들 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 공부 기록 만들기
- 내가 작성한 공부 기록 목록 보기
- 공부 기록 자세히 읽기
- 공부 기록 수정하기
- 공부 기록 삭제하기
- 공개 또는 비공개로 바꾸기
- 내 공부 기록을 제목과 내용으로 검색하기
- 공개된 공부 기록 검색하기

#### 목록 기준

- 최근에 작성한 공부 기록부터 보여줍니다.

### 5.4 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 일을 기록합니다.

예: `저장 버튼 만들기`, `파이썬 복습하기`

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 제목 | 1~100자 |
| 완료 여부 | 미완료 또는 완료 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 완료 날짜와 시간 | 완료로 체크할 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 할 일 만들기
- 할 일을 완료로 체크하기
- 할 일 수정하기
- 할 일 삭제하기
- 공개 또는 비공개로 바꾸기
- `전체`, `남은 일`, `완료한 일`로 나누어 보기

#### 목록 기준

- 완료하지 않은 할 일을 먼저 보여줍니다.
- 같은 완료 상태에서는 최근에 작성한 할 일부터 보여줍니다.

### 5.5 오류 기록

사용자는 오류가 생겼을 때 오류 내용과 해결 과정을 기록합니다. 아직 해결하지 못한 오류도 먼저 저장할 수 있습니다.

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 오류 제목 | 1~100자 |
| 오류 내용 | 1~5,000자 |
| 해결 방법 | 해결 전에는 비워둘 수 있음. 입력할 때는 1~5,000자 |
| 해결 여부 | 미해결 또는 해결 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 해결 날짜와 시간 | 해결 상태로 바꿀 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 오류 기록 만들기
- 미해결 상태로 저장하기
- 해결한 뒤 해결 방법 작성하기
- 해결 여부 바꾸기
- 오류 기록 수정하기
- 오류 기록 삭제하기
- 공개 또는 비공개로 바꾸기
- `전체`, `미해결`, `해결`로 나누어 보기
- 내 오류 기록을 제목과 내용으로 검색하기

#### 목록 기준

- 최근에 작성한 오류 기록부터 보여줍니다.
- 오류를 해결 상태로 바꾸려면 해결 방법을 반드시 입력해야 합니다.

### 5.6 공개 기록

- 사용자는 공개로 설정된 기록을 모아볼 수 있습니다.
- 공개 기록 화면에는 공부 기록, 할 일, 오류 기록을 모두 보여줍니다.
- 사용자는 공개 기록을 공부 기록, 할 일, 오류 기록으로 나누어 볼 수 있습니다.
- 공개된 공부 기록, 할 일, 오류 기록을 검색할 수 있습니다.

### 5.7 댓글과 좋아요

- 공개된 공부 기록과 오류 기록에는 댓글과 좋아요 기능을 제공합니다.
- 공개된 할 일에는 댓글과 좋아요 기능을 제공하지 않습니다.
- 댓글은 1~500자로 입력합니다.
- 첫 버전에서는 댓글에 답글을 다는 기능을 제공하지 않습니다.
- 댓글 작성자는 자신의 댓글을 수정하고 삭제할 수 있습니다.
- 기록 작성자는 자신의 공개 기록에 달린 댓글을 삭제할 수 있습니다.
- 한 사용자는 같은 기록에 좋아요를 한 번만 누를 수 있습니다.
- 좋아요를 다시 누르면 좋아요가 취소됩니다.

### 5.8 신고

- 로그인한 사용자는 공개 기록이나 댓글을 신고할 수 있습니다.
- 신고한 내용은 운영자가 확인할 수 있도록 저장합니다.
- 신고되었다는 이유만으로 기록이나 댓글을 자동으로 삭제하지 않습니다.

### 5.9 검색

첫 버전에서 확정된 검색 범위는 다음과 같습니다.

- 내 공부 기록: 제목과 내용으로 검색
- 내 오류 기록: 제목과 내용으로 검색
- 공개 공부 기록: 검색 가능
- 공개된 할 일: 검색 가능
- 공개된 오류 기록: 검색 가능

내 할 일 검색은 첫 버전에 포함하지 않습니다.

## 6. 어떤 화면이 필요한가요?

첫 버전은 이 문서의 디자인 원칙과 확정된 세부 동작 규칙을 따르며, 다음 화면이 필요합니다.

### 6.1 회원가입 화면

- 이메일, 비밀번호, 닉네임을 입력합니다.
- 회원가입을 요청합니다.

### 6.2 로그인 화면

- 이메일과 비밀번호를 입력합니다.
- 로그인을 요청합니다.

### 6.3 내 기록 홈 화면

- 사용자가 자신의 공부 기록, 할 일, 오류 기록으로 이동할 수 있습니다.
- 밝은 배경과 읽기 쉬운 카드 형태로 핵심 기록을 보여줍니다.
- 메뉴의 이름과 위치를 분명하게 표시합니다.
- 사용자는 계정 설정에서 자신의 닉네임을 변경할 수 있습니다.

### 6.4 공부 기록 화면

- 공부 기록 목록을 봅니다.
- 공부 기록을 작성합니다.
- 공부 기록의 자세한 내용을 읽습니다.
- 공부 기록을 수정하거나 삭제합니다.
- 내 공부 기록을 검색합니다.

### 6.5 할 일 화면

- 할 일 목록을 봅니다.
- 할 일을 작성합니다.
- 완료 여부를 바꿉니다.
- 할 일을 수정하거나 삭제합니다.
- 전체, 남은 일, 완료한 일을 나누어 봅니다.

### 6.6 오류 기록 화면

- 오류 기록 목록을 봅니다.
- 오류 기록을 작성합니다.
- 오류 기록의 자세한 내용을 읽습니다.
- 해결 여부와 해결 방법을 기록합니다.
- 오류 기록을 수정하거나 삭제합니다.
- 전체, 미해결, 해결 상태로 나누어 봅니다.
- 내 오류 기록을 검색합니다.

### 6.7 공개 기록 화면

- 다른 사용자가 공개한 공부 기록, 할 일, 오류 기록을 봅니다.
- 기록 종류별로 나누어 볼 수 있습니다.
- 공개된 공부 기록, 할 일, 오류 기록을 검색합니다.
- 공개된 공부 기록과 오류 기록에 댓글과 좋아요를 사용합니다.
- 공개 기록이나 댓글을 신고할 수 있습니다.

### 6.8 반응형 화면

- 모든 주요 화면은 컴퓨터와 휴대폰 브라우저에서 사용할 수 있어야 합니다.
- 화면 크기에 맞게 내용이 읽기 쉽게 정리되어야 합니다.

## 7. 어디까지 되면 첫 버전이 완성된 것인가요?

다음 항목을 모두 확인하면 첫 버전의 핵심 기능이 완성된 것으로 판단합니다.

- [ ] 사용자가 이메일, 비밀번호, 닉네임으로 회원가입할 수 있습니다.
- [ ] 이미 가입한 이메일로 새 계정을 만들 수 없습니다.
- [ ] 닉네임은 중복되지 않으며 사용자가 나중에 변경할 수 있습니다.
- [ ] 사용자가 이메일과 비밀번호로 로그인할 수 있습니다.
- [ ] 사용자마다 자신의 비공개 기록이 분리되어 있습니다.
- [ ] 다른 사용자는 비공개 기록을 볼 수 없습니다.
- [ ] 공부 기록을 만들고, 목록에서 찾고, 읽고, 수정하고, 삭제할 수 있습니다.
- [ ] 내 공부 기록과 공개 공부 기록을 검색할 수 있습니다.
- [ ] 할 일을 만들고, 완료 여부를 바꾸고, 수정하고, 삭제할 수 있습니다.
- [ ] 할 일을 전체, 남은 일, 완료한 일로 나누어 볼 수 있습니다.
- [ ] 오류를 미해결 상태로 저장할 수 있습니다.
- [ ] 해결 방법을 입력해야 오류를 해결 상태로 바꿀 수 있습니다.
- [ ] 오류 기록을 읽고, 수정하고, 삭제할 수 있습니다.
- [ ] 오류 기록을 전체, 미해결, 해결 상태로 나누어 볼 수 있습니다.
- [ ] 내 오류 기록을 제목과 내용으로 검색할 수 있습니다.
- [ ] 세 종류의 기록이 기본적으로 비공개로 저장됩니다.
- [ ] 사용자가 원하는 기록을 공개로 바꿀 수 있습니다.
- [ ] 로그인한 사용자는 다른 사용자의 공개 기록을 볼 수 있고, 로그인하지 않은 사람은 볼 수 없습니다.
- [ ] 공개된 공부 기록, 할 일, 오류 기록을 모아보고 종류별로 나누어 볼 수 있습니다.
- [ ] 공개된 공부 기록, 할 일, 오류 기록을 검색할 수 있습니다.
- [ ] 공개된 공부 기록과 오류 기록에서 1~500자의 댓글을 작성할 수 있습니다.
- [ ] 댓글 작성자는 자신의 댓글을 수정·삭제할 수 있고, 기록 작성자는 자신의 기록에 달린 댓글을 삭제할 수 있습니다.
- [ ] 한 사용자가 기록 하나에 좋아요를 한 번만 누를 수 있고 다시 누르면 취소됩니다.
- [ ] 로그인한 사용자가 공개 기록이나 댓글을 신고할 수 있습니다.
- [ ] 할 일 완료 날짜와 오류 해결 날짜가 자동으로 저장됩니다.
- [ ] 공부 기록 작성 날짜와 시간이 자동으로 저장됩니다.
- [ ] 컴퓨터와 휴대폰에서 주요 기능을 사용할 수 있습니다.

## 8. 이번에 만들지 않는 기능

- 이메일 확인
- 비밀번호 찾기
- 할 일 마감일
- 할 일 중요도
- 내 할 일 검색
- 댓글 답글

## 9. 화면 디자인 원칙

- 밝은 배경을 사용합니다.
- 목록과 기록은 읽기 쉬운 카드 형태로 보여줍니다.
- 메뉴와 버튼의 이름을 처음 사용하는 사람도 이해하기 쉽게 작성합니다.
- 컴퓨터와 휴대폰에서 모두 사용할 수 있는 반응형 화면으로 만듭니다.
- 화려한 효과보다 기록을 쉽게 작성하고 찾는 데 집중합니다.

## 10. 개발 기술

처음 개발하고 관리하기 쉬운 구성을 사용합니다.

| 구분 | 사용할 기술 | 선택 이유 |
| --- | --- | --- |
| 화면 | React, HTML, CSS, JavaScript | 화면을 기능별 컴포넌트로 나누고 FastAPI와 API로 연결하기 쉬움 |
| 서버 | Python, FastAPI | 프론트엔드와 분리된 API 구조로 회원과 기록 기능을 만들기 쉬움 |
| 실제 서비스 데이터베이스 | Supabase PostgreSQL | 온라인에서 여러 사용자의 데이터를 저장하고 여러 컴퓨터에서 같은 기록을 볼 수 있음 |
| 자동 테스트 데이터베이스 | SQLite3 | 외부 서비스에 연결하지 않고 빠르고 독립적으로 기능을 검사할 수 있음 |

정확한 버전과 데이터베이스 연결 도구는 개발 시작 단계에서 서로 호환되는 안정 버전으로 정합니다. 실제 서비스와 테스트 데이터베이스에서 같은 기능이 동작하도록 특정 데이터베이스에만 있는 기능에 의존하지 않습니다.

## 11. 추가 결정 원칙

첫 MVP의 기능 범위와 기본 동작은 모두 정했습니다. 구현 중 새로운 기능이 필요해져도 임의로 추가하지 않고 별도로 결정합니다.

## 12. 확정한 세부 동작 규칙

### 계정과 입력

- 이메일은 일반적인 `이름@도메인` 형식이어야 하며, 하나의 이메일로 계정을 하나만 만들 수 있습니다.
- 비밀번호는 8자 이상이며 문자와 숫자를 각각 하나 이상 포함해야 합니다.
- 닉네임은 2~20자이며 한글, 영문, 숫자, 밑줄만 사용할 수 있습니다.
- 회원가입이 끝나면 자동으로 로그인하고 홈 화면으로 이동합니다.
- 로그인에 성공하면 홈 화면으로 이동합니다.
- 로그인에 실패하면 이메일 가입 여부를 구분하지 않고 `이메일 또는 비밀번호가 올바르지 않습니다`라고 안내합니다.
- 입력이나 저장에 실패하면 비밀번호만 지우고 나머지 입력은 유지합니다. 잘못된 항목 아래에는 이유를 표시합니다.

### 목록, 변경, 삭제

- 기록이 없으면 안내 문구와 새 기록 작성 버튼을 보여줍니다.
- 기록을 수정해도 처음 작성한 날짜와 시간은 유지합니다.
- 기록이나 댓글을 삭제하기 전에 확인창을 보여줍니다.
- 삭제된 기록과 댓글은 복구할 수 없습니다.
- 기록을 삭제하면 연결된 댓글, 좋아요, 신고도 함께 삭제합니다.
- 완료한 할 일은 다시 미완료로 바꿀 수 있습니다. 미완료로 바꾸면 완료 날짜와 시간을 삭제합니다.
- 해결된 오류는 다시 미해결로 바꿀 수 있습니다. 해결 방법은 유지하고 해결 날짜와 시간은 삭제합니다.
- 댓글이나 좋아요가 있는 기록을 비공개로 바꾸면 해당 댓글과 좋아요는 보존하되 다른 사용자에게 숨깁니다. 기록을 다시 공개하면 그대로 보여줍니다.

### 공개 기록과 검색

- 공개 기록과 검색 결과는 최근에 작성된 기록부터 보여줍니다.
- 공개 공부 기록은 제목과 내용을 검색합니다.
- 공개 할 일은 제목을 검색합니다.
- 공개 오류 기록은 오류 제목과 오류 내용을 검색합니다.
- 검색어 일부가 포함되어도 결과에 보여줍니다.
- 영문 대문자와 소문자를 구분하지 않으며 검색어 앞뒤 공백은 무시합니다.
- 검색어가 비어 있으면 전체 목록을 보여줍니다.

### 댓글과 좋아요

- 댓글은 먼저 작성된 댓글부터 보여줍니다.
- 수정한 댓글에는 정확한 수정 시간 대신 `수정됨`이라고 표시합니다.
- 기록에는 좋아요 개수를 표시합니다.
- 작성자는 자신의 기록에 좋아요를 누를 수 없습니다.

### 신고와 운영

- 신고 사유는 `스팸`, `부적절한 내용`, `개인정보 노출`, `기타` 중 하나를 선택합니다.
- 신고에는 필요한 경우 최대 500자의 자세한 설명을 입력할 수 있습니다.
- 작성자는 자기 기록이나 댓글을 신고할 수 없습니다.
- 한 사용자는 같은 기록이나 댓글을 한 번만 신고할 수 있습니다.
- 운영 권한이 있는 계정은 운영자 전용 화면에서 신고 대상, 신고자, 사유, 자세한 설명, 신고 시간을 확인합니다.
- 첫 버전에서는 별도의 신고 처리 상태와 신고 화면의 제재 기능을 만들지 않습니다.

### 홈과 디자인

- 홈 화면에는 최근 공부 기록 3개, 남은 할 일 5개, 최근 미해결 오류 3개를 보여줍니다.
- 홈 화면에는 각 기록의 전체 목록과 작성 화면으로 이동하는 버튼을 보여줍니다.
- 흰색과 밝은 회색을 바탕으로 사용하고 파란색을 강조색으로 사용합니다.
- 읽기 쉬운 기본 글꼴과 둥근 카드 형태를 사용합니다.
